# 토론 — 은행 전자서명과 블록체인 트랜잭션 서명은 무엇이 다를까

> 수학은 거의 같다. **다른 것은 "누가 보증하는가"다.**

---

## 0. 먼저, 같은 점

둘 다 공개키 암호를 쓰고, 둘 다 같은 구조로 돌아간다.

```
개인키로 서명  →  공개키로 검증  →  내용이 바뀌면 검증 실패
```

실습 1~5에서 만든 코드는 **은행 쪽 알고리즘(RSA)으로 바꿔도 그대로 동작한다.**
`Wallet.createRsa()`로 바꾸기만 하면 된다. 그만큼 기반은 같다.

---

## 1. 알고리즘 — 크기가 다르다

실습 코드가 실제로 측정한 값이다.

| | 알고리즘 | 공개키 | 서명 |
|---|---|---|---|
| 은행 (공인·금융인증서) | RSA 2048 | 294 B | **256 B** |
| 블록체인 | EC secp256k1 | 33~65 B | **~71 B** |

RSA 2048과 EC 256비트는 **보안 강도가 비슷한데 크기는 3~4배 차이**다.

왜 블록체인이 EC를 골랐나 — **블록 공간이 곧 돈이기 때문이다.** 모든 트랜잭션에 서명이 하나씩 붙고, 그게 전 세계 노드에 영구 저장된다. 서명 185바이트 차이가 수수료 차이로 직결된다.

> 은행은 서버에 저장하면 그만이라 이 압박이 없다. 그래서 호환성이 좋은 RSA를 오래 썼다.

---

## 2. 신뢰의 뿌리 — **여기가 진짜 차이다**

### 은행: 공개키가 누구 것인지를 제3자가 보증한다

```
          ┌─────────────┐
          │  인증기관 CA │  "이 공개키는 김민지의 것이 맞습니다"
          └──────┬──────┘
                 │ 서명 (= 인증서)
                 ▼
        김민지의 공개키 ──→ 거래 서명 검증
```

은행이 믿는 것은 **서명 자체가 아니라 CA의 보증**이다.
"이 서명이 유효하다"와 "이 서명을 김민지가 했다"는 다른 문장이고, 그 사이를 CA가 메운다.

### 블록체인: 보증하는 기관이 없다

```
        공개키  ──해시──→  주소
          ▲                 ▲
          └── 이것이 신원 그 자체 ──┘
```

**공개키가 곧 신원이다.** "이 주소가 누구 것인가"를 아무도 모르고, 알 필요도 없다.

증명되는 것은 딱 하나다 — **"이 거래를 승인한 자가 그 주소의 개인키를 갖고 있다."**
그 사람이 김민지인지 홍길동인지는 프로토콜이 묻지 않는다.

---

## 3. 그래서 갈라지는 다섯 가지

| | 은행 | 블록체인 |
|---|---|---|
| **신원 확인** | 실명 — 인증서에 이름이 박힘 | 가명 — 주소만 있음 |
| **키 분실** | 재발급 가능. 자산은 그대로 | **재발급 없음. 자산도 같이 소멸** |
| **키 탈취** | 즉시 폐기(CRL)하면 이후 서명 무효 | **폐기 수단 없음.** 자산을 옮기는 게 유일한 대응 |
| **거래 취소** | 착오송금 반환, 지급정지, 법원 명령 | **없음.** 확정되면 누구도 되돌릴 수 없음 |
| **검증 주체** | 은행 서버 (폐쇄) | 전 세계 노드 (공개) |

### 키 분실이 왜 이렇게 다른가

은행에서 인증서를 날려도 자산은 멀쩡하다. **자산은 은행 DB에 있고, 인증서는 "나임을 증명하는 수단"일 뿐**이기 때문이다. 신분증을 잃어버려도 통장 잔고는 그대로인 것과 같다.

블록체인은 그 분리가 없다. **개인키가 자산에 접근하는 유일한 경로**다. 잃어버리면 그 자산은 영원히 체인에 남은 채 아무도 못 건드린다.

---

## 4. 왜 이렇게 설계했나 — 트레이드오프

블록체인의 불편함은 전부 **"믿을 기관이 없다"는 전제**에서 나온다.

| 없앤 것 | 대가로 얻은 것 |
|---|---|
| CA | 누구의 허가도 없이 계정 생성 |
| 은행 서버 | 특정 기관이 검열·동결할 수 없음 |
| 거래 취소 | 상대가 받았는지 확인할 제3자가 불필요 |
| 계정 복구 | 보관 기관에 대한 신뢰 불필요 |

**좋고 나쁨의 문제가 아니라 전제의 문제다.** 믿을 기관이 있는 환경이라면 은행 방식이 모든 면에서 낫다 — 더 싸고, 빠르고, 실수를 복구할 수 있다.

---

## 5. 한 걸음 더 — 토론해 볼 만한 것

**① 키 분실 문제는 정말 해결 불가능한가?**

기술적으로는 진행 중이다. 계정 추상화(EIP-4337·7702)는 "개인키 하나 = 계정"이라는 등식을 깨서, **소셜 복구**(지인 3명이 동의하면 키 교체)나 **다중 서명**을 넣을 수 있게 한다. 다만 이건 *프로토콜이 아니라 계정 레벨*에서 해결하는 방식이다.

**② 보험·금융에서 블록체인 서명이 은행 방식보다 나은 경우가 있을까?**

핵심 질문은 **"믿을 중앙 기관이 실제로 없는가"** 하나다.
- 한 회사 안에서 돌아가는 계약이면 → 중앙 DB가 모든 면에서 낫다
- **서로 믿지 않는 여러 기관이 같은 장부를 봐야 한다면** → 검토할 가치가 있다 (예: 보험사 간 중복 청구 탐지, 재보험 정산)

**③ 실명성과 가명성을 섞을 수 있을까?**

실제로 금융권 시도가 이 지점에 몰려 있다 — 체인은 공개로 두되 **주소와 실명의 연결은 별도 레이어에서 관리**하는 방식. 트래블룰(FATF)이 요구하는 것이 정확히 이것이다.

---

## 한 줄 요약

> **은행 서명은 "CA가 보증한 당신"을 증명하고,
> 블록체인 서명은 "이 키의 주인"을 증명한다.**
>
> 전자는 신원을 증명하고, 후자는 권한만 증명한다.
